# TeddyTales — анимация главного героя

Рабочая ветка под анимацию мишки: спецификация рига, инструменты проверки,
локальная лаборатория `.riv` и Flutter-модуль персонажа.

> В `main` это пока не уходит. Всё собирается и тестируется здесь; перенос —
> когда продукт будет готов.

Делает **одну комнату — «Игра»** (главный экран, КП раздел 3). Весь раздел 4
коммерческого предложения — «Анимация персонажа» — обслуживает именно её:
**108 клипов, все в этой комнате**. Разбивка — `node tools/bin/teddy.mjs clips`.

Остальные экраны вне границ: сцена рождения, магазин, мини-игры готовки,
обучение, гардероб, каталог физических мишек, панель управления.

## Что здесь

```
rig/bear_rig.json          единый источник истины: кости, control-узлы,
                           свойства View Model, состояния
rig/animation_catalog.json каталог 108 клипов из раздела 4 КП
rive/bear/                 проект Rive CLI (RML), генерируется из спеки
tools/                     CLI: дерево рига, проверка слоёв, кодогенерация, сборка .riv, лаборатория
lab/                       лаборатория .riv в браузере
app/                       Flutter-модуль: BearView + BearController
docs/                      конвенция именования, MCP, бриф художнику, открытые вопросы
handoff/                   приём файлов от художника и проверка именования
rive/scripts/              заготовка Luau-скрипта затухания
```

## Быстрый старт

```bash
cd tools && npm install

node bin/teddy.mjs doctor     # состояние проекта одним экраном
node bin/teddy.mjs tree       # дерево рига
node bin/teddy.mjs clips      # каталог клипов против обещаний КП
npm run build:riv             # спека -> RML -> .riv -> app/assets (нужен Rive CLI)
npm run lab                   # лаборатория: http://127.0.0.1:4321
```

```bash
cd app
flutter pub get
flutter analyze && flutter test
```

## Лаборатория .riv

Главный инструмент на время сборки рига. Открывает `.riv` (перетаскиванием,
через выбор файла или прямо из репозитория) и даёт:

- **Панель «Контракт»** — сверяет файл с `rig/bear_rig.json`: артборды обоих
  героев, имя State Machine, каждое свойство View Model и его тип. Красное
  здесь означает, что Flutter не привяжется. Это главное, ради чего она есть:
  расхождение имён ловится до сборки приложения, а не на устройстве.
- **Data Binding** — живые ползунки, переключатели и кнопки триггеров,
  собранные автоматически по содержимому файла. Вложенные View Model
  обходятся рекурсивно и показываются теми же путями со слэшем
  (`Button/State_1`), что используются в Dart.
- **Симулятор затухания** — крутит показатели по заглушкам из спеки, с
  ускорением до 60×, чтобы увидеть переход в грустное состояние за секунды,
  а не за сутки.
- Переключение артборда и State Machine, выбор `fit`, счётчик FPS, лог.

Работает офлайн: wasm-рантайм отдаётся из `tools/node_modules`, не с CDN.

## Один источник истины

`rig/bear_rig.json` — единственный файл, который правится руками. Из него
генерируются `app/lib/src/bear_rig_contract.dart` и `lab/rig_spec.generated.js`:

```bash
cd tools && npm run gen:dart
```

Имя части живёт сразу в четырёх местах — у художника, в редакторе Rive, в State
Machine и в коде Flutter. Генерация нужна, чтобы расхождение находил
инструмент, а не тестировщик.

## Приём работы художника

```bash
node tools/bin/teddy.mjs layers > handoff/expected_layers.txt
node tools/bin/teddy.mjs check handoff/incoming/bear.svg
```

Понимает `.svg`, `.json` и `.txt`. Отчёт отдельно показывает опечатки
(переименовать — минута) и отсутствующие слои (перерисовывать). Бриф —
`docs/artist-handoff.md`.

## Порядок работ по ригу

Скелет, View Model и State Machine **не собираются руками** — они генерируются
из спеки в RML и собираются Rive CLI в `.riv` (`docs/rive-cli-workflow.md`):

1. `cd tools && npm run build:riv` — каркас мишки в `app/assets/rive/bear.riv`.
2. `npm run lab` → «Load from repo»: контракт зелёный, в логе — смены
   состояний при изменении `mood`, `stage`, по триггерам.
3. `rive login && rive rive/bear --once --rev=bear.rev` — файл для редактора.
4. В Rive Editor: заменить плейсхолдеры артом, покрасить веса, поставить IK,
   довести тайминг клипов.
5. Экспортировать `.rev` обратно → `rive create --from-rev` → сверка со спекой
   лабораторией.
6. `cd app && flutter analyze && flutter test`.

## Важное про API

PDF-ТЗ раздел 6 описывает legacy-рантайм: `RiveAnimation.asset` и
`stateMachineInputs` в `rive: 0.14.x` либо отсутствуют, либо помечены
устаревшими. Управление построено на Data Binding. Разбор — в
`docs/runtime-api-notes.md`.
