# TeddyTales — модуль анимированного персонажа

Flutter-модуль мишки на Rive: состояние персонажа, показатели ухода и вся связь
с ригом через State Machine.

Реализовано по **`docs/tz-animator.md`** (контракт с ригом, раздел 8.1) и по
той части **`docs/tz-app.md`**, что описывает персонажа — показатели ухода,
стадии роста, характеры, одежду. Остальное из КП — магазин, мини-игры,
обучение, каталог физических мишек, платежи, панель управления — пока не
трогалось.

## Структура

```
lib/
  main.dart                     дев-панель: все входы State Machine руками
  bear/
    bear.dart                   barrel-экспорт модуля
    bear_rig_spec.dart          контракт с ригом: имена входов + enum'ы значений
    bear_stats.dart             пять показателей ухода + затухание
    bear_mood_policy.dart       свёртка пяти показателей в один вход mood
    bear_state.dart             полное состояние персонажа + слоты одежды
    bear_controller.dart        API для игровой логики (чистый Dart)
    bear_rig_sink.dart          интерфейс «передать в риг»
    bear_rig_binding.dart       единственный файл, знающий про API Rive
    bear_view.dart              виджет: загрузка .riv, подключение рига
docs/
  tz-animator.md                ТЗ для аниматора — контракт с ригом
  tz-app.md                     состав приложения из КП
  rig-naming.md                 чеклист приёмки рига
  runtime-api-note.md           расхождения документов и как они разрешены
  tz-rive-animation.md          устаревший черновик, оставлен ради MCP-раздела
```

### Почему так разложено

`BearController`, `BearState`, `BearCareStats` и `BearMoodPolicy` не импортируют
`package:rive`. Это даёт две вещи: логику можно гонять в тестах без нативных
библиотек `rive_native`, и замена рантайма не задевает игровую логику —
переписывается только `bear_rig_binding.dart` + `bear_view.dart`.

Весь контакт с ригом идёт через интерфейс `BearRigSink` — это граница между
приложением и анимацией.

## Контракт с ригом

Артборд и State Machine — `bear_main`. Приложение управляет персонажем только
через входы (раздел 8.1 ТЗ аниматора): «никаких других способов запуска
анимаций быть не должно».

| Вход | Тип | Откуда берётся значение |
| --- | --- | --- |
| `stage` | 1–5 | `BearState.stage`, меняется только через `growUp()` |
| `mood` | 0–5 | считается из пяти показателей, см. ниже |
| `trait` | 0–5 | `BearState.trait` |
| `variant` | 0–1 | случайно перед `trg_eat` и `trg_pet` |
| `is_walking` | bool | `BearState.isWalking` |
| `skin` | 0–1 | `BearState.skin` |
| `outfit_id` / `headwear_id` / `shoes_id` / `accessory_id` | 0–8 / 0–3 / 0–2 / 0–3 | `BearState.outfit` |
| 11 `trg_*` | Trigger | методы `BearController` |

### Пять показателей → один `mood`

КП задаёт пять показателей 0–100 (еда, гигиена, сон, игра, любовь), ТЗ
аниматора — один вход `mood` с шестью кодами. Как одно превращается в другое,
не написано нигде, поэтому правило вынесено в отдельный класс `BearMoodPolicy`
и помечено как допущение:

1. Из трёх показателей со своим idle (еда → `hungry`, сон → `sleepy`,
   гигиена → `dirty`) берётся самый низкий; если он ниже 30 — играет он.
2. `dirty` пропускается на стадиях 1–2: клипа `idle_dirty` для них нет.
3. Иначе по среднему: ниже 40 — `sad`, от 80 — `happy`, между — `normal`.

Пороги и приоритеты меняются одним конструктором. **Требует подтверждения.**

## Запуск

Платформенные папки в репозитории не хранятся:

```bash
flutter create .          # создаст android/ ios/ и т.д.
flutter pub get
flutter run
```

Требования: Flutter >= 3.32, Dart SDK >= 3.8 (этого требует `rive` 0.14.x).
Нативные библиотеки `rive_native` скачиваются автоматически. Если сборка
падает:

```bash
flutter clean && flutter pub get
dart run rive_native:setup --verbose --clean --platform <macos|ios|android|...>
```

## Тесты

```bash
flutter test
```

48 тестов: показатели и затухание, свёртка в `mood`, контроллер, соответствие
значений входов разделу 8.1. Тестов рига нет — без реального `.riv` тестировать
нечего.

## Как подключить готовый риг

1. Положить `bear_main.riv` в `assets/rive/`.
2. Запустить — плейсхолдер сменится мишкой. Дев-панель покажет, отзывается ли
   риг на каждый вход.
3. Если какого-то входа в машине нет, приложение не упадёт: в дев-лог уйдёт
   сообщение, какого именно. Сверить с `lib/bear/bear_rig_spec.dart`.

## Использование из приложения

```dart
final bear = BearController();

BearView(controller: bear);           // на экране

bear.feedBear();                      // trg_eat + еда вверх
bear.petBear();                       // trg_pet + любовь вверх
bear.washBear();
bear.playWithBear();
bear.putToSleep();
bear.growUp();                        // trg_stage_up, затем stage++
bear.showHappy();                     // после верного ответа в обучении
bear.setOutfit(const BearOutfit(outfitId: 3, headwearId: 1));
bear.restoreState(savedState);        // загрузка прогресса с сервера
```

## Открытые вопросы

- **Свёртка показателей в `mood`** — правило придумано здесь, в документах его
  нет. Подтвердить приоритеты и пороги.
- **Скорости затухания и безопасный предел** — сейчас заглушки в
  `BearDecayConfig`. По КП 15.4 они настраиваются с панели управления, то есть
  должны приезжать с сервера.
- **Серверное время** (КП 1.5) — локальный таймер годится только для открытой
  сессии; отыгрыш «сколько прошло, пока приложение было закрыто» обязан
  считаться на сервере. Backend-стек не подтверждён.
- **Момент взросления** — по КП 5.7 зависит от общего ухода и настраивается с
  сервера. `growUp()` только исполняет, решения не принимает.
- **Сцена рождения** — сдаётся и как `.riv`, и как mp4. Чем показывать в
  приложении, не решено; виджета под неё пока нет.
- **Характер** — по КП 7.3 формируется из совокупности действий за период.
  Формулы нет, `trait` пока только выставляется снаружи.
