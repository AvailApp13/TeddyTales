# Выпуск iOS: Codemagic → TestFlight

Порядок настройки один раз, дальше — одна кнопка. Сборку запускаем вручную;
всё, что после нажатия, идёт без рук: тесты, подпись, `ipa`, загрузка в
App Store Connect и раздача тестировщикам.

Конфигурация сборки — `codemagic.yaml` в корне репозитория.

**Значения проекта** (не секреты; секрет — только файл `.p8`, он в репозиторий
не попадает никогда):

```
Bundle ID:        com.teddytales.app
Apple ID:         6804642179
Issuer ID:        69a6de82-0693-47e3-e053-5b8c7c11a4d1
Ключ в Codemagic: «Codemagic Admin 2» (Key ID WKU89FQ3YM, роль «Менеджер приложения»)
```

Важно про роль ключа: «Разработчик» для публикации не хватает — сборка
пройдёт, а загрузка в TestFlight упадёт с ошибкой доступа. Нужен «Менеджер
приложения». Старый ключ с ролью «Разработчик» использовать нельзя, да и
`.p8` от него повторно не скачивается.

Он уже прописан в `ios/Runner.xcodeproj` и в `codemagic.yaml`. Если ваша
компания хочет другой (например по своему домену), скажите — поменяю в обоих
местах. **Менять после создания приложения в App Store Connect нельзя**,
поэтому решаем сейчас.

---

## Шаг 1. Зарегистрировать Bundle ID

Это то, на чём вы сейчас стоите: App Store Connect не даст создать приложение,
пока идентификатора не существует.

1. [developer.apple.com/account](https://developer.apple.com/account) →
   **Certificates, Identifiers & Profiles** → **Identifiers** → **+**
2. Тип: **App IDs** → **App**
3. Description: `TeddyTales`
4. Bundle ID: **Explicit**, значение `com.teddytales.app`
5. Capabilities не трогаем — пуши и покупки добавим, когда дойдём до них.
   Их можно включить позже, идентификатор при этом не меняется.
6. **Continue** → **Register**

## Шаг 2. Досоздать приложение в App Store Connect

Вернуться в форму «Новое приложение» и обновить страницу — теперь
`com.teddytales.app` появится в списке.

| Поле | Значение |
| --- | --- |
| Платформы | iOS |
| Название | Teddy Tales |
| Основной язык | Русский |
| ID пакета | com.teddytales.app |
| SKU | `teddytales-ios-001` |
| Пользовательский доступ | Полный доступ |

SKU — внутренний артикул, его не видит никто, кроме вас, и поменять его потом
нельзя. Название «Teddy Tales» должно быть свободно в App Store; если Apple
скажет, что занято — берём другое, на Bundle ID это не влияет.

После создания: **App Information** → запишите **Apple ID** приложения. Это
число вида `6740123456`, оно понадобится на шаге 5.

## Шаг 3. Ключ App Store Connect API

Через него Codemagic будет загружать сборки. Пароль от Apple ID ему не нужен
и давать его не надо.

1. App Store Connect → **Users and Access** → **Integrations** →
   **App Store Connect API** → вкладка **Team Keys**
2. **+**, имя `Codemagic`, роль **App Manager**
3. Скачать файл `.p8` — **он выдаётся ровно один раз**, второй раз скачать
   нельзя, только выпустить новый ключ. Положите его в надёжное место.
4. Записать **Issuer ID** (общий для команды) и **Key ID** (у ключа в списке)

## Шаг 4. Подключить ключ к Codemagic

Codemagic → **Teams** → ваша команда → **Integrations** → **Developer Portal**
→ **Add key**:

| Поле | Значение |
| --- | --- |
| Name | **`Codemagic Admin 2`** |
| Issuer ID | из шага 3 |
| Key ID | из шага 3 |
| Private key | файл `.p8` из шага 3 |

Имя должно побуквенно совпадать с блоком `integrations` в `codemagic.yaml` —
сейчас там `Codemagic Admin 2`. Если имена разойдутся, сборка упадёт с
«No matching profiles found» ещё до первого шага: автоподпись молча не
подключится.

## Шаг 5. Переменная с ID приложения

Codemagic → приложение → **Environment variables**:

| Name | Value | Group | Secret |
| --- | --- | --- | --- |
| `APP_STORE_APP_ID` | `6804642179` | `appstore` | не нужен |
| `CERTIFICATE_PRIVATE_KEY` | RSA-ключ, см. ниже | `appstore` | **обязателен** |

`CERTIFICATE_PRIVATE_KEY` — приватный RSA-ключ, которым Codemagic выпускает
сертификат подписи у Apple. Генерируется один раз на Mac:

```
ssh-keygen -t rsa -b 2048 -m PEM -f ~/Desktop/codemagic_key -q -N ""
cat ~/Desktop/codemagic_key | pbcopy
```

Вторая команда кладёт содержимое ключа в буфер обмена — остаётся вставить его
в поле Value. Файл с Рабочего стола после этого можно убрать в надёжное место:
если ключ потеряется, сертификат просто выпустят заново.

Переменная нужна, чтобы сборка сама узнала номер последнего билда в TestFlight
и поставила следующий. TestFlight требует строго возрастающий номер, а руками
это забывается на третьей сборке.

## Шаг 6. Группа тестировщиков

App Store Connect → **TestFlight** → **Internal Testing** → **+** →
название группы **`Internal testers`** → добавить себя.

Имя тоже должно совпасть: на него ссылается `beta_groups` в `codemagic.yaml`.
Внутренние тестировщики получают сборку сразу, без ревью Apple.

## Шаг 7. Подключить репозиторий

Codemagic → **Add application** → GitHub → `AvailApp13/TeddyTales` →
конфигурация: **codemagic.yaml**.

Codemagic сам найдёт файл в корне и увидит воркфлоу **iOS → TestFlight**.

## Шаг 8. Первая сборка

**Start new build** → workflow `iOS → TestFlight` → ветка с вашим кодом.

Что произойдёт: установка зависимостей → `flutter analyze` и `flutter test`
(95 тестов) → выпуск сертификата и профиля → сборка `ipa` → загрузка в
App Store Connect → раздача группе `Internal testers`.

Первая сборка идёт дольше остальных: Codemagic выпускает сертификат
распространения и профиль. Дальше они переиспользуются.

Через 5–15 минут после загрузки Apple закончит обработку, и сборка появится
в TestFlight на телефоне.

## Что уже сделано в репозитории

**Создан каталог `ios/`.** Его не было вообще — проект собирался только под
веб, и Codemagic'у было нечего собирать. Теперь есть Xcode-проект с Bundle ID
`com.teddytales.app` и отображаемым именем «Teddy Tales».

**В `Info.plist` добавлен `ITSAppUsesNonExemptEncryption = false`.** Без него
TestFlight на каждой сборке спрашивает про экспортный контроль и держит билд,
пока не ответите руками. Приложение не использует нестандартное шифрование,
так что ответ всегда один и тот же — проще ответить один раз в коде.

**`pubspec.lock` теперь коммитится.** Раньше он был в `.gitignore`. Для
приложения это ошибка: без него CI может собрать другой набор версий пакетов,
чем у вас локально, и падение будет невоспроизводимым.

**Версия Flutter в `codemagic.yaml` закреплена** на 3.44.9, а не `stable`.
`stable` меняется под ногами, и сборка, которая шла вчера, завтра падает на
чужом релизе.

## Автоматический запуск на каждый push

Если захотите, чтобы сборка шла сама — раскомментировать в `codemagic.yaml`:

```yaml
    triggering:
      events:
        - push
      branch_patterns:
        - pattern: main
          include: true
```

Пока не советую: каждая сборка — это минуты платного времени на macOS-агенте,
а мы сейчас коммитим часто. Разумный момент включить — когда появится ветка
`main` с релизным кодом и работа пойдёт через pull request'ы.

## Если сборка упала

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `No matching profiles found` | Bundle ID не зарегистрирован или не совпал | сверить шаг 1 и `BUNDLE_ID` в `codemagic.yaml` |
| «No matching profiles found», лог пустой | имя интеграции в yaml не совпало с именем ключа в Codemagic | сверить `integrations.app_store_connect` с Manage keys |
| `App not found` при публикации | не создано приложение или неверный `APP_STORE_APP_ID` | шаги 2 и 5 |
| `Beta group not found` | нет группы или имя другое | шаг 6, имя точно `Internal testers` |
| Падает на `flutter test` | сломаны тесты | чинить код, гейт стоит намеренно |
| `The build number must be higher` | номер не вырос | проверить `APP_STORE_APP_ID` — без него номер берётся со счётчика Codemagic |

Логи сборки Codemagic отдаёт целиком, включая `xcodebuild` — они лежат в
артефактах. Пришлите, разберу.
