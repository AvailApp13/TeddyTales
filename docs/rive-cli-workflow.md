# Rive CLI — как риг живёт в репозитории

Rive CLI (v1.1.1) собирает `.riv` и `.rev` из **текста**: RML-разметка сцены +
Luau-скрипты + ассеты. Это и есть мост между спецификацией в репозитории и
редактором Rive, где красят арт и веса.

    rive --version                 # 1.1.1
    rive doctor                    # окружение, авторизация, проект

## Установка

macOS: `brew install --cask rive-app/cli/rive-cli`. Windows и Linux — скрипт
установки с rive.app/docs (раздел CLI).

Linux вручную, как сделано в этой среде (бинарнику нужны EGL/GLES):

    apt-get install -y libegl1 libgles2 libgl1
    curl -sL https://releases.rive.app/cli/v1.1.1/rive-linux-x64.tar.gz -o rive.tar.gz
    sha256sum rive.tar.gz   # 41684e9d99fea98e01c2c155e07ec985130b95b640410dc0fbe4ca30c271a7d5
    mkdir -p /opt/rive-cli && tar xzf rive.tar.gz -C /opt/rive-cli
    ln -sf /opt/rive-cli/rive /usr/local/bin/rive

В архиве лежат `docs/` (встроенный справочник, `rive docs <тема>`) и
`samples/`. Справочник — единственная полная документация RML; читать
`rive docs format` перед любой правкой разметки.

## Что генерируется, что делается руками

| Генерируется из спеки (`teddy gen:rml`) | Руками в Rive Editor |
|---|---|
| два артборда `Bear_Boy` / `Bear_Girl` 1024×1024 | настоящий арт вместо плейсхолдеров |
| скелет: `root`, `root_body`, `root_arm_left/right` с длинами и углами | подгонка длин и поворотов под рисунок |
| все 55 узлов спеки с точными именами и иерархией | **скиннинг**: `Skin` / `Tendon` / `Weight` — сами Rive пишут, что руками это «самая болезненная часть формата» |
| control-узлы `ctrl_*` | IK на руках, look-at на голове (см. ниже) |
| 4 пустых группы слотов одежды на нужных костях | варианты одежды внутри слотов + `Solo` для переключения |
| View Model `BearVM`: 26 свойств, перечисления `stage`/`trait`/`mood`, экспортированный инстанс | — |
| State Machine «State Machine 1», 10 слоёв, 320 переходов **с условиями по данным** | тайминг, easing, переходы между вариантами |
| заготовки всех 112 клипов каталога + 2 позы для blend осанки | движение как таковое: сейчас это 1–3 дорожки-«маячка» на клип |
| листенер касания → триггер `tap` (КП 3.1) | — |
| blend осанки по `care_index` (КП 5.7, 6.2) | — |

Не подключено к State Machine (нет триггера в View Model — вопрос к
Заказчику): `move_*` (перемещение), `trait_*_idle` (покой по характеру),
`var_*` и `emote_*_b` (вариативность — нужен `random="true"` и веса).

## Устройство State Machine

**Слои покоя — по одному на стадию** (`idle_newborn` … `idle_adult`). Каждый
активен, только пока `stage` равен своей стадии, внутри — 6 состояний по
`mood`. Так сделано не ради красоты: переход из `AnyState` в текущее состояние
перезапускал бы клип каждый кадр, поэтому в слоях покоя все переходы явные,
состояние → состояние (42 на слой).

**Слои по триггерам** (`action`, `emotion`, `growth`, `trait`) стартуют из
`AnyState`: триггер расходуется в кадре срабатывания, повторного входа не
будет. Условие — триггер **и** стадия (или характер), выход — по концу клипа
обратно в пустое состояние `none`.

**Слой `posture`** — `BlendState1DViewModel` по `care_index`: 0 — заброшенная
поза, 100 — ухоженная. Приложение считает `care_index` как среднее пяти
показателей (`BearVitals.careIndex`).

Проверить, что машина реально переключается, а не просто загрузилась:
лаборатория пишет каждую смену состояния в лог (`state → idle_sad_crawler`).

## Цикл

    cd tools && npm run build:riv

Это: `gen:rml` → `rive --verify` → `rive inspect` (проблемы) → `rive --once`
→ копия `.riv` в `app/assets/rive/bear.riv`. Затем `npm run lab` и «Load from
repo» — контракт должен быть зелёным, лог — показывать смены состояний.

Ручные шаги того же цикла:

    node bin/teddy.mjs gen:rml
    rive ../rive/bear --verify
    rive inspect ../rive/bear --summary
    rive ../rive/bear --once            # -> rive/bear/build/bear.riv

## Обмен с редактором

**Из репозитория в редактор** — нужен `.rev`, а его экспорт требует `rive login`
(это ограничение CLI, не наше):

    rive login
    rive rive/bear --once --rev=bear.rev

`.rev` открывается в Rive Editor как обычный файл. Красьте арт и веса там.

**Из редактора в репозиторий** — экспортируйте `.rev` и:

    rive create rive/bear_from_editor --from-rev=bear.rev
    rive inspect rive/bear_from_editor --summary

Полученный `scene.rml` — это ваш файл в текстовом виде. Сверка со спекой
делается лабораторией (загрузить собранный `.riv`) или по именам узлов:

    rive inspect rive/bear_from_editor --json | jq '[..|objects|select(.name?)|.name]'

Синхронизация в обратную сторону («syncing changes from the editor file back
into your local project») в CLI помечена как *coming soon*, поэтому пока
источник истины по структуре — `rig/bear_rig.json` + генератор, а по арту и
весам — файл редактора.

## IK и look-at (руками, но по образцу)

Из документации CLI, `rive docs rigging`:

- локоть: `IKConstraint` на второй кости цепочки с `parentBoneCount="1"`;
- голова следит за пальцем: `IKConstraint` с `parentBoneCount="0"` на кости
  головы — это «look-at», ничем другим в формате не делается;
- `IKConstraint` обязан сидеть на `Bone`, иначе весь файл не импортируется.

В сгенерированном скелете цепочка руки — `root_arm_*` (кость) → `forearm_*` →
`hand_*` (группы-плейсхолдеры по спеке PDF). Для IK предплечье и кисть должны
стать костями — это решение стоит принять в редакторе вместе с артом.

## Система координат кости — проверено экспериментом

Документация CLI этого не говорит прямо, поэтому измерено рендером
(`RootBone x=100 length=200` и три маркера):

| Что | Откуда считаются координаты |
|---|---|
| `Node` / `Shape` внутри кости | от **начала** кости (`x=0` — это `RootBone.x`), ось x — вдоль кости |
| дочерняя `Bone` | стартует в **кончике** родителя, `rotation` — относительно родителя |
| `RootBone` внутри `Bone` | свои `x`/`y` от **начала** родительской кости (как у `Node`, не как у дочерней `Bone`) — так ставятся плечи и бёдра, которые не лежат на кончике `root`. Проверено измерением: при отсчёте от кончика руки и ноги уходили вниз ровно на длину `root` |

Генератор (`tools/lib/gen_rml.mjs`, `walk`) держит для каждого узла два кадра:
для детей-Node — начало кости, для детей-Bone — кончик. Art- и control-узлы
получают `rotation = -угол кости`, чтобы внутри них всё оставалось в экранной
ориентации, а поворот в анимациях задаётся дельтой к этой базе.

## Ограничения этой среды

- `--screenshot` в контейнере без GPU отдаёт только фон (проверено на
  сэмплах Rive) — визуальная проверка идёт через лабораторию в Chromium.
- `--rev` и `--publish` требуют `rive login` — делается на вашей стороне.
- Скрипты Luau, собранные без `--publish`, не подписаны и не работают в
  web-рантайме; в приложении Flutter ограничения нет.
