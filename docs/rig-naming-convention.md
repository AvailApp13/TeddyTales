# Конвенция именования рига

Источник — PDF-ТЗ раздел 3, за основу взята структура из
[2d-inc/Flare-Flutter, example/teddy](https://github.com/2d-inc/Flare-Flutter/tree/master/example/teddy):
формат старый (`.flr`), сам файл не переиспользуется, но именование проверено в
проде.

Машиночитаемый источник истины — `rig/bear_rig.json`. Всё остальное
(Dart-контракт, спека лаборатории, список для художника) **генерируется** из
него. Руками правится только он.

    node tools/bin/teddy.mjs tree      # дерево с родителями
    node tools/bin/teddy.mjs doctor    # что готово, что ещё нет
    cd tools && npm run gen:dart       # перегенерировать контракт

## Настройка редактора

Rive: Workspace → Admin → Options → Naming convention → **snake_case**.

## Виды узлов

| Вид | Что это |
|---|---|
| `bone` | кость, невидима |
| `control` | невидимый «рычаг» для управления группой частей |
| `art` | слой, который рисует художник |

## Control-узлы

Отдельные невидимые узлы, через которые двигаются группы — чтобы анимировать
взгляд одним ключом, а не шестью:

| Узел | Управляет |
|---|---|
| `ctrl_face` | лицом целиком |
| `ctrl_eyes` | направлением взгляда, двигает оба глаза разом |
| `ctrl_pupils` | зрачками |
| `ctrl_mouth` | ртом |
| `ctrl_nose` | носом |
| `ctrl_eyebrow_left` / `ctrl_eyebrow_right` | бровями |

## Два решения, которые стоит знать

**Суффикс стороны в цепочке рук (D1).** PDF пишет цепочку обобщённо
(`forearm → forearm_light → hand → hand_light → finger_N_nail`). Рук две, имена
внутри артборда должны быть уникальны, поэтому каждое звено раскрыто в
`_left` / `_right`.

**Родитель рук (D2).** PDF перечисляет `root_arm_left` / `root_arm_right` на
одном уровне с `root_body`, поэтому они дети `root`, а не `body`. Следствие:
руки **не наследуют** движение корпуса. Если squash-and-stretch корпуса должен
тянуть руки — перепривязать `root_arm_*` под `body` в редакторе и поправить
`rig/bear_rig.json`.

Оба решения и остальные записаны в `rig/bear_rig.json → decisions`.
