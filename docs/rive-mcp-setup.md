# Rive MCP — подключение

По PDF-ТЗ раздел 4.

> **Основной канал теперь — Rive CLI**, а не MCP: он не требует открытого
> редактора, работает на Linux и собирает `.riv` из текста, который лежит в
> репозитории. См. `docs/rive-cli-workflow.md`. MCP остаётся для работы прямо
> в открытом редакторе. Rive от MCP не отказался (блог, 30.04.2026:
> «продолжаем работать над MCP»).

## Что это

Официальный MCP-сервер, встроенный в **Rive Editor Early Access** (в
Production-версии редактора его нет). Позволяет управлять открытым файлом Rive
на естественном языке из внешнего AI-инструмента.

## Подключение

Сервер — локальный HTTP-эндпоинт `http://127.0.0.1:9791/mcp`. Поднимается
только пока открыт Rive Editor (Early Access) на той же машине, где работает
Claude Code.

В этом репозитории конфиг уже лежит в `.mcp.json` — при запуске Claude Code из
корня проекта сервер подхватится сам. Запасные варианты:

**GUI** — Настройки → Connectors → «+» → Add custom connector → вставить имя и
URL `http://127.0.0.1:9791/mcp` → Add.

**Терминал:**

    claude mcp add --transport http rive http://127.0.0.1:9791/mcp

Если редактор закрыт, сервер недоступен — это нормально, не ошибка конфигурации.

## Как дать доступ к редактору из облачной сессии

Сервер MCP слушает `127.0.0.1` на **вашем Mac**. Облачная сессия Claude Code
живёт в контейнере и до него не дотягивается — это не ошибка конфигурации,
а география. Два способа это обойти, от простого к «максимальному».

### Способ 1 — сессия на вашем компьютере

Claude Desktop, или в терминале в папке проекта:

    claude remote-control

Тогда `.mcp.json` из репозитория подхватится сам, MCP Rive будет доступен
нативно, и лаборатория с CLI работают на той же машине, где открыт редактор.
Самый надёжный путь для работы «в редакторе».

### Способ 2 — туннель к редактору из облака

На Mac, при открытом Rive Editor (Early Access):

    brew install cloudflared
    cloudflared tunnel --url http://127.0.0.1:9791

Команда напечатает адрес вида `https://<случайные-слова>.trycloudflare.com`.
Дальше два варианта:

**а) Нативно, с перезапуском сессии.** В настройках облачного окружения
(меню окружения в заголовке сессии → Edit):
- переменная окружения `RIVE_MCP_URL=https://<адрес>.trycloudflare.com/mcp`;
- в Network access разрешить домен `*.trycloudflare.com` (или уровень
  доступа шире).

`.mcp.json` подставляет `RIVE_MCP_URL`, и новая сессия увидит инструменты
Rive как свои.

**б) Без перезапуска — клиент в репозитории.** Пришлите адрес в чат:

    RIVE_MCP_URL=https://<адрес>.trycloudflare.com/mcp node tools/bin/teddy.mjs mcp:ping
    node tools/bin/teddy.mjs mcp:tools
    node tools/bin/teddy.mjs mcp:call <инструмент> '{"...": "..."}'

Сетевой домен всё равно должен быть разрешён в окружении.

### Безопасность туннеля — прочитайте

Быстрый туннель cloudflared **не имеет авторизации**: любой, кто узнает адрес,
сможет управлять вашим открытым файлом Rive. Адрес случайный и живёт, пока
работает команда, но правила простые:
- поднимать туннель только на время сеанса и закрывать `Ctrl-C` сразу после;
- не публиковать адрес нигде, кроме этого чата;
- держать в редакторе открытым только рабочий файл мишки.

Если нужен постоянный канал — именованный туннель Cloudflare с Access-политикой
или SSH-туннель; это отдельная настройка на вашей стороне.

## Что MCP реально умеет (подтверждено официально)

- создание и редактирование View Models (свойства данных);
- создание State Machine (состояния, переходы, слои);
- работа с Layouts и Shapes;
- настройка градиентов на заливках и обводках;
- component data context (привязка Model/Path компонентов);
- relative data binding через вложенные view model'и.

## Что остаётся ручной работой

- **Расстановка костей на импортированных слоях.** Документированных
  подтверждений, что MCP делает это надёжно, нет. В куда более зрелом Blender
  MCP официально сказано, что риггинг с покраской весов и IK «нереалистичен с
  текущими возможностями MCP».
- **Полировка ощущения живости** — тайминг, вес движения. Это глаз, не API.

## Отсюда — порядок работ

1. Слои от художника проверить на именование: `node tools/bin/teddy.mjs check <файл>`.
2. Кости и control-узлы расставить **вручную** в редакторе по
   `rig/bear_rig.json` (дерево: `node tools/bin/teddy.mjs tree`).
3. Дальше подключать MCP — на View Model, State Machine и поведенческую логику
   поверх готового рига.
4. Экспортировать `.riv` в `app/assets/rive/bear.riv`.
5. Проверить файл в лаборатории: `cd tools && npm run lab`.

Тариф Rive: Cadet, $9/мес — безлимитный экспорт `.riv` для продакшена и Early
Access, который нужен для MCP.

## Скриптинг (Luau)

PDF 5 предлагает повторить паттерн из официального туториала Sasquatch:
скрипт с input-переменной, привязанной к свойству View Model; затухание по
секундам; рост по тапу/действию; blend state, управляемый этим значением.

Заготовка под наш случай — `rive/scripts/bear_decay.lua`. Важная оговорка: по
КП 15.4 скорости показателей настраиваются из панели управления, то есть
авторитет — сервер, а не скрипт внутри `.riv`. Скрипт годится для превью в
редакторе; в приложении затуханием управляет `BearController.startDecay()`.

Референс-файлы для разбора:
- стартовый: rive.app/community/files/25775-48125-sasquatch-starter-file
- финальный: rive.app/community/files/25774-48147-interactive-sasquatich
