# «Мишки» — витрина сайта TeddyTales (КП 12)

> **14.10, позже в тот же день: витрина спрятана.** Заказчик после
> разговора с Ириной: teddytales.com — магазин для отправок по всему миру,
> в ценах растаможка и налоги. В «Мишках» вместо витрины — портрет мишки и
> «Скоро здесь появятся мишки TeddyTales» (`kStoreCatalogShown = false` в
> `lib/screens/catalog_screen.dart`, к серверу экран не обращается).
> Ежечасная загрузка с сайта на паузе (миграция 0031, задание cron
> выключено, не удалено). Всё остальное ниже цело и включается обратно:
> `kStoreCatalogShown = true` и
> `select cron.alter_job(jobid, active := true) from cron.job where jobname = 'store-catalog-refresh';`
> Вернёмся при выходе на международные площадки. Для Китая заказчик ждёт
> контакт по ценам (Taobao, Douyin) — там свой канал покупки.

**Решение Ирины 14.10:** настоящих мишек покупают на сайте
[teddytales.com](https://teddytales.com). В разделе «Мишки» (кнопка на лапе)
приложение показывает их товары и по «Купить на сайте TeddyTales» открывает
страницу товара окном браузера поверх игры. Адрес, оплата и доставка — на
сайте, заказ сразу попадает в их систему продаж.

| КП | Как выполнено |
|---|---|
| 12.1 каталог, данные как в официальном магазине | товары, фото, цены и наличие берутся с сайта раз в час |
| 12.2 карточка: размер, одежда, мех, редкость | размер — из меток сайта («30cm») или названия; метки серий и меха (Mohair, Story Bear…) — чипами |
| 12.3 оформление с проверкой адреса | оформление Shopify на их сайте |
| 12.4 WeChat Pay, Alipay, PayPal | способы оплаты их сайта — ⚠ уточнить у Ирины, включены ли WeChat Pay и Alipay |
| 12.5 заказ в систему продаж Заказчика | заказ создаётся прямо в их магазине |
| 15.2 заказы в панели | заказы — в их Shopify (там же выгрузка); метка «из приложения» показывает, какие пришли из игры |

Старый экран заказа с адресом и «Оплата подключается на этапе интеграции»
убран.

## Сервер (миграция 0030)

- Сайт сделан на Shopify, список товаров открыт: `/products.json`.
- `refresh_store_catalog()` забирает его (расширение `http`) и
  раскладывает в `store_catalog`. Задание cron `store-catalog-refresh` —
  каждый час в 23 минуты. Вручную: `select public.refresh_store_catalog();`
- Через API её не вызвать (отказ «только для сервера»), иначе любой гонял
  бы наш сервер на их сайт.
- Приложение читает `store_catalog()` — адрес магазина, метку и товары
  видимых разделов в порядке сайта.
- Разделы — по типу товара на сайте: `Bear` → мишки, `Clothing
  accessories` → одежда, остальные зверята (котики, лисы, Blind Box…) →
  друзья. Подарочная карта и услуги не показываются.
- Товар исчез с сайта — прячется (`category = null`), вернулся — снова
  виден.
- 14.10 задание выключено (`cron.alter_job(…, active := false)`, миграция
  0031), пока витрина спрятана.
- `game_config.store_catalog`:
  - `url` — адрес магазина;
  - `show` — видимые разделы, по умолчанию все три. ⚠ Ирина не отвечала,
    показывать ли одежду и друзей; убрать раздел — убрать его из `show`,
    без новой сборки;
  - `utm` — метка в ссылках (`utm_source=teddytales_app`).

14.10: 221 товар — 57 мишек, 91 одежда, 73 друзей; в наличии 152.

## Приложение

- `lib/catalog/store_catalog.dart` — разбор, порядок (в наличии сверху),
  размер, метки, ссылка на товар.
- `lib/screens/catalog_screen.dart` — вкладки «Мишки / Одежда / Друзья»,
  сетка карточек, страница товара: галерея, варианты, кнопка.
- Откуда витрина: сохранённая (без сети, КП 1.1) → снимок в сборке
  `assets/catalog/store_snapshot.json` → свежая с сервера.
- Ссылка: `https://teddytales.com/products/<handle>?variant=<id>&utm_source=teddytales_app&utm_medium=catalog&utm_campaign=<язык>`.
  Вариант — только если у товара есть выбор. По `utm_source` магазин видит
  в своей статистике покупки из игры, по `utm_campaign` — язык.
- Открывается окном поверх приложения: Safari View Controller на iPhone,
  Custom Tabs на Android (`url_launcher`, `queries` в манифесте), в вебе —
  новой вкладкой.
- Названия товаров — по-английски, как на сайте. Цены в долларах.
- Apple и Google так разрешают: физический товар покупается вне магазинов
  приложений (App Store 3.1.3(e)), комиссии нет.

## Превью-артефакт

В артефакте запросы к серверу и картинки с чужих сайтов закрыты, поэтому
веб-сборка показывает снимок из сборки, а миниатюры берёт рядом со
страницей: `web/store/thumbs/<id>.jpg` (480 × 576, JPEG; прозрачные PNG
сайта — на белом). Без миниатюры — с CDN магазина.

⚠ Пока витрина спрятана (`kStoreCatalogShown = false`), миниатюры в
артефакт не публикуются (с версии 209): артефакт держит не больше 511
файлов, а 221 миниатюра заняла бы место лапок девочки. В репозитории они
остаются; витрину вернули — опубликовать `store/` снова.

Обновить снимок (новые товары в превью):

1. `assets/catalog/store_snapshot.json` — ответ `store_catalog()` (POST
   `/rest/v1/rpc/store_catalog` с публичным ключом).
2. Миниатюры: CDN магазина из этой среды закрыт, качать через сервер.
   14.10 — временной функцией `_tt_thumb(id)` (база по `http` берёт
   `images[1]&width=480`, отдаёт base64), после — тело заменено пустым.

## ⚠ Supabase: подтверждение «опасных» команд

С 14.10 на `DROP`, `REVOKE`, `DELETE` и `apply_migration` Supabase ждёт
ручного подтверждения заказчика; без него через минуту — таймаут, и
ничего не применяется. Поэтому 0030 применена по частям через
`execute_sql`, а запись в `schema_migrations` внесена отдельно. Перед такой
командой — предупредить заказчика.

Осталось убрать с подтверждением: пустые пробные функции `_tt_probe2()` и
`_tt_thumb(bigint)` (ничего не делают).
