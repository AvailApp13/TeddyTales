# Личный кабинет и кошелёк

Сделано 24.09 по просьбе заказчика: «регистрировать пользователя на отдельный
ID, чтобы к нему привязывался счёт… чтобы у каждого пользователя был свой
личный кабинет». Сервер — проект Supabase `bwvwzzquiepghebskaib`, миграция
`supabase/migrations/0010_personal_account.sql`.

## Кто есть кто

```
auth.users  (учётная запись, id)          ← создаётся сама при первом запуске
   │ 1:1                                    (анонимно, КП 1.2)
public.players (личный кабинет, id = тот же)
   │  coins        — единственный кошелёк: еда, магазин, награды
   │  locale, player_age, quiet_hours
   │ 1:N (сейчас один)
public.pets (мишка)  named_at — давали ли имя (КП 2.3)
   └ pet_stats, pet_outfit, care_events, name_moderation
players → inventory, room_layout, edu_progress, coin_ledger, purchases
```

- Каждый видит только свои строки: RLS по `auth.uid()`.
- Кошелёк клиент читает, но не пишет. Менять баланс может только
  `wallet_change` — внутренняя функция, из приложения её не вызвать. Каждое
  движение — строка в `coin_ledger` с причиной (`welcome`, `dish:pasta`,
  `recipe:cookie`, `buy:table`, `care:wash`, `edu:colors`, `test_floor`).
- Нехватка монет — ошибка `TT402`, приложение возвращает монеты на экране.
- Вход через Apple/Google/почту (КП 1.3) **привязывается к той же учётной
  записи** (`linkIdentity`): id не меняется, кошелёк и мишка остаются. На новом
  телефоне вход тем же Apple ID открывает этот же кабинет (КП 1.4).
- Удалить аккаунт — `delete_my_account()`: учётная запись, кабинет, мишка,
  покупки уходят каскадом (App Store 5.1.1(v)).
- Сотрудники панели (по приглашению) кабинета с мишкой не получают.

## Справочник знаков зодиака (миграция 0011)

`zodiac_signs`: 12 знаков — даты начала и конца (включительно), символ,
стихия, названия ru/en/zh. `zodiac_for(date)` — знак по дате, Козерог через
Новый год. `local_date(момент, метаданные)` — дата у человека по его поясу.
Проверено: каждый из 366 дней года попадает ровно в один знак.

## Функции для приложения (только после входа)

| Функция | Что делает |
| --- | --- |
| `open_account()` | вход в кабинет при запуске: находит мишку, отмечает визит, поднимает тестовый кошелёк, отдаёт снимок |
| `feed_dish(pet, dish)` | блюдо за монеты; цена и сытость — настройка `dishes` |
| `complete_recipe(pet, recipe)` | награда и сытость — настройка `recipes` |
| `record_care`, `buy_item`, `complete_level` | как раньше, но через кошелёк кабинета |
| `rename_pet(pet, name, locale)` | имя 2–15 знаков, фильтр слов, ставит `named_at` |
| `delete_my_account()` | удалить всё |

Снимок содержит блок `account`: `coins`, `is_anonymous`, `providers`
(`email`, `apple`, `google`…), `email`, `email_confirmed`, `registered_at`,
`player_age`, `locale`; блок `zodiac` — знак мишки из справочника целиком.

Цены блюд, награды рецептов и порог тестового кошелька правятся в
`game_config` (панель, КП 15.4), без выпуска приложения.

## Регистрация по почте (24.09)

Стартовая страница: «Войти через Apple», «Войти через Google» (ждут App Store
и Google Play — пока пускают без регистрации), ниже «Регистрация по почте».
Alipay, QQ, WeChat спрятаны (`_SignInMethod.shown`). Кто вошёл, стартовую
страницу больше не видит — сессия хранится на телефоне; «Выйти» в профиле
возвращает на неё.

Что происходит при регистрации: Supabase заводит учётную запись →
триггер `handle_new_user` создаёт кабинет (250 монет, до порога 5000 на
испытаниях), мишку с днём рождения = моментом регистрации и знаком зодиака по
дате у человека (телефон присылает свой пояс, `tz_offset_min`), 12 стартовых
предметов. Профиль показывает: день рождения, знак (♎ Весы), раздел «Личный
кабинет» — почта, дата регистрации, кошелёк.

## Что включить в панели Supabase

Authentication → **Sign In / Providers** → **Email**:

1. **Enable Email provider** — включено (по умолчанию так и есть).
2. **Confirm email** — на время испытаний **выключить**. Иначе после
   регистрации нужно открыть письмо, а встроенная почта Supabase шлёт письма
   **только адресам участников проекта** и не больше нескольких в час —
   тестировщики писем не получат. Для запуска: включить обратно и подключить
   свою почту (Authentication → **Emails → SMTP Settings**, например Resend
   или Mailgun).
3. Authentication → **URL Configuration** → **Site URL**: куда ведёт ссылка
   из письма. У нового проекта там `http://localhost:3000` — ссылка
   подтвердит почту, но откроет пустую страницу. Поставить адрес сайта
   TeddyTales, когда он будет.

Там же, в Sign In / Providers:

4. **Allow anonymous sign-ins** — для «Пропустить» и кнопок Apple/Google,
   пока они не подключены. Выключено — эти кнопки пускают без сервера.
5. **Allow manual linking** — привязка Apple к уже созданному кабинету.
6. **Apple** — Client IDs `com.teddytales.app`, когда восстановится Apple ID.
