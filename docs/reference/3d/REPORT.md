# Мишка в 3D: источник ракурсов для разбора на детали

Отчёт по эксперименту, который должен закрыть претензию «части тела будто
отдельно, всё растягивается кодом». Задача была не «нарисовать мишку заново»,
а получить **правильный источник** для нарезки деталей: одного фронтального
фото для рига мало — при повороте головы или взмахе лапы неоткуда взять
пиксели, и код начинает растягивать имеющиеся.

## Что сделано

### 1. Фото → 3D

| | |
|---|---|
| Вход | `docs/reference/bear-source-v2.png` (утверждённый эталон) |
| Модель | `meshy_v7_image_to_3d`, ultra_mode, symmetry auto, 30 000 полигонов |
| Job | `04e5f3e1-0a80-4796-8369-070a9a9b155d` |
| Стоимость | 44 кредита |
| Результат | GLB, 5 141 664 Б, 31 112 треугольников, 34 863 вершины, одна PBR-текстура |

Габарит модели (после нормализации): 1.148 × 1.905 × 0.805.

GLB лежит в облаке Higgsfield:
`hf_20260912_060151_04e5f3e1-0a80-4796-8369-070a9a9b155d.glb`.
В репозиторий не кладётся: 5 МБ бинарника, который перегенерируется за минуту.

**Важно про доступ:** CDN Higgsfield (`d8j0ntlcm91z4.cloudfront.net`,
`d2ol7oe51mr4n9.cloudfront.net`) закрыт egress-прокси нашей среды — прямой
`curl` даёт 403. Скачивание и рендер делаются внутри песочницы Higgsfield
(`sandbox_exec`), результат выносится через base64. Прокси не обходится.

### 2. 3D → ракурсы

`turnaround-4v.webp` — 4 из 8 отрендеренных ракурсов (0°, 45°, 90°, 180°).
Рендер: Playwright + headless Chromium (`--use-gl=angle --use-angle=swiftshader`)
+ three.js 0.160, три источника света, ровный студийный свет, без теней.

Грабля: с флагом `--use-gl=swiftshader` контекст WebGL молча теряется и
кадры выходят пустыми. Рабочая комбинация — именно `angle` + `swiftshader`.

### 3. Ракурс → плюш

`plush-restore-test.webp` — верхний ряд две генерации целиком, нижний ряд
кроп головы.

| | |
|---|---|
| Модель | `gpt_image_2_5`, variant flare, quality high, 2K, фон прозрачный |
| Референс 1 | рендер 3D-модели (задаёт ракурс и позу) |
| Референс 2 | студийное фото настоящей игрушки (задаёт внешний вид) |
| Jobs | `55e64e09-e3e1-4199-99c3-b19aa4802423`, `847039f0-0978-417e-9eb4-fcba6cd5b82a` |

## Вердикт

**Геометрия 3D-модели годится.** Силуэт, пропорции, форма остроконечного
капюшона, уши сквозь капюшон, жёлтые шорты с подворотами, одна белая
пуговица, ярлычок на правом бедре — всё на месте. Это тот же мишка, не
«похожий».

**Поверхность 3D-модели не годится напрямую.** Meshy отдаёт гладкий
пластик: ворса нет, глаза матовые без блика, мордочка сглажена, уши в
профиль читаются плоскими накладками. Показывать такой рендер заказчику
нельзя — это ровно то, за что уже дважды заворачивали.

**Связка 3D + фото решает проблему.** На третьем шаге плюш возвращается:
ворсинки, блик в глазах, вышитый нос, текстура хлопка на капюшоне,
прозрачный фон, 2K. Это уже уровень, который можно резать на детали.

**Слабое место связки:** `gpt_image_2_5` слушает референс позы нестрого —
запрошенные 45° вернулись почти фронтальными. Для поворотов корпуса нужен
либо более жёсткий структурный контроль, либо — что для нас важнее — это
просто не нужно: риг живёт в 3/4 и фронте, а нужны нам не повороты корпуса,
а **варианты деталей** (глаза открыты/прищур/закрыты, рот в четырёх видах,
лапы в трёх положениях), где поза общая, а меняется одна часть.

## Что дальше

1. Сгенерировать лист деталей: голова с четырьмя выражениями, глаза в трёх
   состояниях, лапы и ноги в нужных положениях — каждый элемент отдельной
   генерацией с прозрачным фоном, тот же тандем референсов.
2. Прогнать через `tool/make_rig_v4.py` (обрезка, дефриндж, упаковка в WEBP).
3. Собрать риг через `tool/riv_rig.py`: детали подменяются, а не тянутся
   сеткой — деформация остаётся только там, где она физична (дыхание корпуса).
