## 1. О проекте и задаче

TeddyTales — мобильная игра-тамагочи для iOS и Android. Пользователь получает
плюшевого мишку, ухаживает за ним, кормит, играет и растит от новорождённого до
взрослого за две недели реального времени. Мишка — существующий бренд-персонаж
компании, у него есть утверждённый внешний вид, который нельзя менять.

Задача аниматора: собрать интерактивного анимированного персонажа в Rive,
которым управляет приложение. Это не видеоролик и не набор гифок — это
интерактивный файл, где приложение в реальном времени переключает состояния и
запускает реакции.

Уровень исполнения — премиальный. Ключевое требование: мишка должен выглядеть
живым в любой момент, даже когда пользователь ничего не делает. Дыхание,
моргание, микродвижения ушей и головы обязательны во всех состояниях покоя.

## 2. Формат и программное обеспечение

| Параметр | Требование |
| --- | --- |
| Программа | Rive (rive.app), актуальная версия редактора |
| Формат сдачи | `.riv` (экспорт) + исходный файл проекта Rive |
| Тип анимации | Векторная, скелетная (bones) с mesh-деформацией |
| Частота | 60 fps |
| Рабочий холст | 1024 × 1024 px, персонаж по центру, запас по краям 5% |
| Цветовое пространство | sRGB |
| Растровые вставки | Не допускаются. Вся графика — вектор внутри Rive |
| Именование | Латиница, нижний регистр, snake_case (`idle_happy`, `ear_left`) |

## 3. Исходные материалы

Аниматору передаются векторные исходники персонажей (мальчик и девочка) от
бренда, брендбук (палитра, пропорции, правила внешнего вида), фотографии
реальных плюшевых игрушек и референсы образов из соцсетей бренда.

Если исходники приходят одним слоем, разбор на части и построение рига входят в
работу аниматора и обсуждаются отдельной строкой.

## 4. Разбор персонажа на части (обязательная структура)

### 4.1 Голова

```
head                          основа головы
ear_left / ear_right          уши, с внутренней частью отдельным объектом
muzzle                        мордочка (светлое пятно)
nose                          нос
mouth                         рот, с возможностью деформации
                              (улыбка, открыт, грусть, «о»)
eye_left / eye_right          глаз целиком
pupil_left / pupil_right      зрачок отдельно — обязательно, для взгляда
eyelid_left / eyelid_right    веко отдельно — обязательно, для моргания
brow_left / brow_right        брови — для эмоций
blush_left / blush_right      щёчки-румянец, управляемая прозрачность
```

### 4.2 Тело

```
body                                       туловище
arm_left_upper / arm_left_lower            рука в двух сегментах
arm_right_upper / arm_right_lower
paw_left / paw_right                       кисти отдельно
leg_left_upper / leg_left_lower            нога в двух сегментах
leg_right_upper / leg_right_lower
foot_left / foot_right                     стопы отдельно
tail                                       хвостик, если предусмотрен брендом
```

### 4.3 Порядок слоёв

Строго снизу вверх: дальняя рука → дальняя нога → тело → ближняя нога →
ближняя рука → голова → элементы лица → слои одежды. Одежда всегда выше
соответствующей части тела и никогда не вплавлена в неё.

## 5. Система одежды

16 предметов одежды и аксессуаров, надеваются и снимаются в любых сочетаниях.

- **5.1 Точки крепления** — одежда привязывается к тем же костям, что и части
  тела: комплект к `body`, головной убор к `head`, обувь к `foot_left` /
  `foot_right`.
- **5.2 Слоты** — четыре: `outfit`, `headwear`, `shoes`, `accessory`.
  Независимы, включаются и выключаются по отдельности.
- **5.3 Видимость** — каждый предмет отдельная группа с управляемой
  видимостью, переключается из приложения.
- **5.4 Деформация** — одежда деформируется вместе с телом (mesh на тех же
  костях), не «съезжает» при движении.
- **5.5 Тестовый набор** — аниматор делает 4 тестовых предмета (по одному на
  слот); остальные 12 добавляются по той же схеме после утверждения.

## 6. Стадии роста — 5 стадий, 2 героя

| # | Название | Особенности |
| --- | --- | --- |
| 1 | Новорождённый | лежит, голова крупная, глаза чаще закрыты, движения минимальные |
| 2 | Ползающий малыш | сидит и ползает, начинает опираться на лапы |
| 3 | Первые шаги | стоит неуверенно, покачивается, делает первые шаги |
| 4 | Подрастающий | уверенно стоит и ходит, активная жестикуляция |
| 5 | Взрослый | финальные пропорции, полный набор движений и эмоций |

Мальчик и девочка используют **один общий риг**. Различия — цвет шерсти, размер
и одежда, реализуются сменой графики внутри того же файла. Два отдельных набора
анимаций не принимаются.

## 7. Перечень анимаций — 108 клипов

### 7.1 Состояния покоя (idle), зациклены — 28

| Состояние | Кол-во | Описание |
| --- | --- | --- |
| `idle_normal` | 5 | по одному на стадию — спокойное состояние |
| `idle_happy` | 5 | показатели высокие: активнее движения, приподнятые уши |
| `idle_sad` | 5 | показатели низкие: опущенная голова и уши, вялые движения |
| `idle_hungry` | 5 | голоден: смотрит по сторонам, трогает живот |
| `idle_sleepy` | 5 | хочет спать: полуприкрытые веки, зевание, покачивание |
| `idle_dirty` | 3 | **только стадии 3–5**: почёсывается, отряхивается |

### 7.2 Действия ухода, одноразовые с возвратом в idle — 28

| Действие | Кол-во | Описание |
| --- | --- | --- |
| `act_eat` | 5 | из бутылочки (стадии 1–2), из миски (3–5) |
| `act_wash` | 4 | стадии 2–5: умывание, брызги, отряхивание |
| `act_sleep` | 5 | укладывается, засыпает, сопит (зацикленная фаза сна) |
| `act_wake` | 5 | просыпается, потягивается |
| `act_play` | 4 | стадии 2–5: играет с игрушкой, подпрыгивает |
| `act_pet` | 5 | реакция на поглаживание: жмурится, тянется к руке |

### 7.3 Перемещение — 6

`crawl` (1, стадия 2) · `walk_unsure` (1, стадия 3) · `walk` (2, стадии 4–5,
зациклено) · `turn` (2, стадии 4–5).

### 7.4 Переходы между стадиями — 4

`stage_up_1_2` … `stage_up_4_5`, по 2–3 секунды. Выразительная анимация:
свечение, вспышка, персонаж «вырастает» в кадре.

### 7.5 Характеры — 18

Шесть типов: активный, любознательный, ласковый, спокойный, самостоятельный,
замкнутый.

- `idle_trait_*` — 6, уникальный idle на характер (стадии 4–5)
- `reaction_trait_*` — 12, по две реакции на характер: на касание и на угощение

Различия должны читаться без подписей — по позе, темпу движений, выражению.

### 7.6 Дополнительные реакции (вариативность) — 16

`act_eat` вариант B (5) · `act_pet` вариант B (5) · `idle_bonus` (6, редкие
«пасхалки»: чихнул, погнался за бабочкой, потянулся).

Приложение выбирает вариант случайно.

### 7.7 Эмоциональные акценты — 8

`emo_happy_burst` · `emo_sad` · `emo_surprise` · `emo_love`, по 2 каждого,
стадии 4–5.

### 7.8 Сцена рождения (отдельный файл)

Отдельная сцена, **не входит в основной State Machine**. 20–30 секунд:
кроватка и одеяло, дышащее вместе с мишкой → мягкие световые эффекты и
звёздочки → первый вдох → пробуждение и осмотр → первый плач → успокаивается и
смотрит в камеру (стоп-кадр для карточки рождения).

Сдаётся и как файл Rive, и как видеорендер 1080×1920, 60 fps, без звука и
текста (субтитры накладывает приложение).

## 8. State Machine — управление из приложения

Все анимации собираются в State Machine с именем **`bear_main`**. Приложение
управляет персонажем **только** через перечисленные ниже входы. Никаких других
способов запуска анимаций быть не должно.

### 8.1 Входы (Inputs)

| Вход | Тип | Диапазон | Назначение |
| --- | --- | --- | --- |
| `stage` | Number | 1–5 | текущая стадия роста |
| `mood` | Number | 0–5 | 0 normal · 1 happy · 2 sad · 3 hungry · 4 sleepy · 5 dirty |
| `trait` | Number | 0–5 | тип характера (0 активный … 5 замкнутый) |
| `variant` | Number | 0–1 | выбор варианта анимации для вариативности |
| `is_walking` | Boolean | | включает цикл ходьбы |
| `trg_eat` | Trigger | | кормление |
| `trg_wash` | Trigger | | умывание |
| `trg_sleep` | Trigger | | уложить спать |
| `trg_wake` | Trigger | | разбудить |
| `trg_play` | Trigger | | игра |
| `trg_pet` | Trigger | | поглаживание (касание экрана) |
| `trg_stage_up` | Trigger | | переход на следующую стадию |
| `trg_emo_happy` | Trigger | | радость |
| `trg_emo_sad` | Trigger | | огорчение |
| `trg_emo_surpr` | Trigger | | удивление |
| `trg_emo_love` | Trigger | | проявление любви |
| `outfit_id` | Number | 0–8 | надетый комплект (0 — без одежды) |
| `headwear_id` | Number | 0–3 | головной убор |
| `shoes_id` | Number | 0–2 | обувь |
| `accessory_id` | Number | 0–3 | аксессуар |
| `skin` | Number | 0–1 | 0 мальчик, 1 девочка |

### 8.2 Правила переходов

- Любой Trigger прерывает текущий idle, проигрывается один раз и возвращает
  персонажа в актуальный idle по значениям `stage`, `mood` и `trait`.
- Смена `stage` происходит только через `trg_stage_up`, никогда мгновенно.
- Все переходы плавные, blend не менее 0,15 с. Резкие переключения не
  допускаются.
- Персонаж никогда не остаётся в статичной позе: при отсутствии команд всегда
  играет соответствующий idle.
- Если приложение задаёт несочетаемые значения, State Machine обязана
  отработать корректно и вернуться в `idle_normal`, а не зависнуть.

## 10. Что сдаётся

1. `bear_main.riv` — экспорт с работающей State Machine и всеми 108 клипами
2. Исходный проект Rive — со структурой слоёв и именованием
3. `birth_scene.riv` — сцена рождения
4. Видеорендер сцены рождения — 1080×1920, 60 fps, mp4, без звука
5. 4 тестовых предмета одежды, по одному на слот, встроенные в файл
6. Краткая документация — список клипов, входов и правил (1–2 страницы)
7. Демо-страница — html или Rive Preview с переключателями всех состояний

## 11. Этапы работы и приёмка

| Этап | Содержание | Результат приёмки |
| --- | --- | --- |
| 1 | Разбор персонажа, риг, тестовая поза | риг двигается, части названы по схеме |
| 2 | Стадии роста, состояния покоя | 5 стадий, 28 idle, дыхание и моргание |
| 3 | Действия ухода, перемещение, переходы | 38 клипов, State Machine переключается |
| 4 | Характеры и вариативность | 18 + 16 клипов, различия читаются |
| 5 | Эмоции, одежда, сцена рождения | 8 клипов, 4 предмета, сцена готова |
| 6 | Сдача | всё по разделу 10, проверка на устройстве |

Приёмка каждого этапа — не более 3 рабочих дней.

## 12. Критерии качества

Персонаж выглядит живым в покое (дыхание, моргание, микродвижения) · переходы
плавные · характеры читаются без подписей · повторные действия не выглядят
одинаково · одежда не съезжает ни в одной анимации · внешний вид соответствует
брендбуку · файл укладывается в ограничения и держит 60 fps.

## 13. Что не входит в задачу аниматора

Анимация интерфейса (делается в Lottie) · отрисовка предметов игры · отрисовка
16 предметов одежды (только система креплений и 4 тестовых) · звук ·
интеграция файла в приложение (делает разработка).
