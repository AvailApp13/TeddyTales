# TeddyTales — модуль анимации мишки

Ветка `claude/hero-animation-setup-exnpp8`. В `main` ничего из этого пока не
уходит: собираем и тестируем здесь, переносим, когда продукт будет готов.

## Границы

Здесь только анимированный персонаж (раздел 4 КП) и сцена питомца на главном
экране (КП 3.1). Магазин, мини-игры, обучение, e-commerce, бэкенд — вне
границ, не трогать.

## Один источник истины

`rig/bear_rig.json` — имена костей, control-узлов, свойств View Model и
состояний. Из него **генерируются**:

- `app/lib/src/bear_rig_contract.dart`
- `lab/rig_spec.generated.js`

Эти два файла править руками нельзя. После изменения спеки:

    cd tools && npm run gen:dart

Смысл: имя живёт в четырёх местах сразу — у художника, в редакторе Rive, в
State Machine и в коде Flutter. Расхождение ловится инструментом, а не на
проде.

`rig/animation_catalog.json` — каталог 108 клипов из раздела 4 КП.

## Команды

    cd tools && npm install

    node bin/teddy.mjs doctor    # что готово, что ещё нет
    node bin/teddy.mjs tree      # дерево рига
    node bin/teddy.mjs clips     # каталог клипов против обещаний КП
    node bin/teddy.mjs layers    # список слоёв для художника
    node bin/teddy.mjs check <f> # проверить присланные слои
    npm run lab                  # лаборатория .riv на localhost:4321

    cd app && flutter analyze && flutter test

## Порядок работ

Кости ставятся **руками** в редакторе — MCP это не умеет надёжно
(`docs/rive-mcp-setup.md`). MCP подключается дальше, на View Model, State
Machine и логику поверх готового рига.

## Чего не делать

- Не использовать `RiveAnimation.asset` и `stateMachineInputs` — их нет либо
  они устарели в `rive: 0.14.x`. Управление через Data Binding.
  Подробности — `docs/runtime-api-notes.md`.
- Не использовать `rive-flutter-legacy`.
- Не превращать заглушки скоростей затухания в продакшен-значения: по КП 15.4
  они настраиваются с сервера.
- Не подгонять каталог клипов под 108: расхождение 112/108 — вопрос к
  Заказчику, а не ошибка счёта (Q1).
