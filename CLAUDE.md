# TeddyTales — модуль анимации мишки

Ветка `claude/hero-animation-setup-exnpp8`. В `main` ничего из этого пока не
уходит: собираем и тестируем здесь, переносим, когда продукт будет готов.

## Границы — только эта ветка и этот репозиторий

Работа идёт **только** в `AvailApp13/TeddyTales`, ветка
`claude/hero-animation-setup-exnpp8`. Ни в какие другие репозитории
(`moodytoy`, `avail.*` и прочие) не заходить, не клонировать, не читать —
даже «посмотреть». Это прямое указание Руслана.

## Герой — только мальчик

Референс — плюшевый мишка-мальчик: голубая толстовка с капюшоном, жёлтые
шорты. Утверждённый мишка — `handoff/reference/bear_boy_v2_full.png` (Higgsfield,
без бирки, прозрачный фон, 1333×2000). Из него режутся слои рига
`handoff/layers_v2/` (`tools/scripts/split_full_bear.py`: 11 слоёв полного кадра —
стопы, шорты, корпус толстовки, лапы, рукава, уши, лицо, капюшон; ставятся одним
общим трансформом, в покое складываются обратно пиксель в пиксель; под соседями
у слоёв есть скрытые продолжения на случай движения). Позы без редактора
проверяет `tools/scripts/simulate_pose.py`, в редактор слои ставит
`tools/scripts/place_layers_v3.mjs`. Лапы, рукава и лицо двигаются целиком
(не тянутся — решение D15), руки лежат под корпусом толстовки со скрытым
запасом у плеча; капюшон и шорты — сетки с весами (`tools/scripts/skin_layers.mjs`,
D14). За лицом — скрытая подкладка капюшона.
**Сборка и привязка сеток — только в позе покоя:** если в редакторе идёт
проигрывание, кости стоят в случайном кадре и привязка портится. Всё, что
меняет слои или сетки, запускать через
`node scripts/with_rest_pose.mjs -- <команда>` (замораживает анимацию в покое,
потом возвращает ключи). Картинку слоя нельзя подменить свойством —
`scripts/replace_layers.mjs` (после замены капюшона/шорт — снова
`skin_layers.mjs`). Редактор изредка молча теряет запись (масштаб слоя 100 %,
ключи в покое) — после правок проверять масштабы слоёв и ключи; ключи
восстанавливает `scripts/demo_moves.mjs` (он же — демо-сценарий). С
него же снята сетка `rig/bear_proportions.json`
(`tools/scripts/measure_bear_v2.py`). Отдельные части из Higgsfield лежат в
`handoff/parts_v2/` — это скрытый запас под зоны, которых на кадре не видно
(макушка под капюшоном, плечи, бёдра). Фото из `handoff/reference/*.jpg` и
старые вырезы — только референс, для арта не использовать.
**Девочку (белая, зелёная кофта, розовая юбка) не учитывать** — прямое
указание Руслана. `Bear_Girl` в спеке остаётся как место под второго героя
по КП, но вся работа по сетке, ригу и арту идёт по мальчику.

## Границы — только комната «Игра»

Эта ветка делает **одну комнату — «Игра»** (главный экран, КП раздел 3).
В остальные экраны не заходить и ничего в них не менять.

Подтверждено подсчётом: весь раздел 4 КП — «Анимация персонажа» — обслуживает
эту комнату. **108 клипов, все в комнате «Игра».**

| КП | Группа | Клипов |
|---|---|---|
| 4.2 | Состояния покоя | 28 |
| 4.3 | Действия ухода | 28 |
| 4.4 | Перемещение | 6 |
| 4.5 | Переходы между стадиями | 4 |
| 4.6 | Анимации характеров | 18 |
| 4.7 | Вариативность | 16 |
| 4.8 | Эмоциональные акценты | 8 |
| | **Итого** | **108** |

Плюс 4 слота одежды (КП 4.9) — привязаны к костям, работают во всех клипах.

**Вне границ:** сцена рождения (КП 2.1, 4.10) — отдельный экран-ролик до входа
в комнату, 6 клипов, размечена в каталоге только для полноты. Магазин,
мини-игры готовки, обучение, гардероб, каталог физических мишек, e-commerce,
панель управления, бэкенд — не трогать.

Отдельные клипы **переиспользуются** на других экранах (эмоция радости на
экране задания — КП 9.3; покой при примерке в гардеробе — КП 10.6), но
рисуются один раз здесь. Это не повод заходить в те экраны.

Разметка по экранам живёт в `rig/animation_catalog.json → surfaces`,
проверяется командой `node tools/bin/teddy.mjs clips`.

## Один источник истины

`rig/bear_rig.json` — имена костей, control-узлов, свойств View Model и
состояний. Из него **генерируются**:

- `app/lib/src/bear_rig_contract.dart`
- `lab/rig_spec.generated.js`

Эти два файла править руками нельзя. После изменения спеки:

    cd tools && npm run gen:dart

Смысл: имя живёт в четырёх местах сразу — у художника, в редакторе Rive, в
State Machine и в коде Flutter. Расхождение ловится инструментом, а не на
проде.

`rig/animation_catalog.json` — каталог 108 клипов из раздела 4 КП.

## Команды

    cd tools && npm install

    node bin/teddy.mjs doctor    # что готово, что ещё нет
    node bin/teddy.mjs tree      # дерево рига
    node bin/teddy.mjs clips     # каталог клипов против обещаний КП
    node bin/teddy.mjs layers    # список слоёв для художника
    node bin/teddy.mjs check <f> # проверить присланные слои
    npm run build:riv            # спека -> RML -> .riv -> app/assets
    npm run lab                  # лаборатория .riv на localhost:4321
                                 #   лог показывает смены состояний: state -> idle_sad_crawler

    cd app && flutter analyze && flutter test

## Порядок работ — через Rive CLI

Rive CLI (`rive`, v1.1.1) собирает `.riv` из текстовой разметки RML. Генератор
`teddy gen:rml` пишет `rive/bear/scene.rml` из спеки: скелет, все 55 узлов,
View Model, перечисления, State Machine с переходами по данным, заготовки
всех клипов. Полный цикл — одна команда:

    cd tools && npm run build:riv     # gen:rml -> verify -> inspect -> .riv -> app/assets

`rive/bear/scene.rml` и `rive/bear/rive.yaml` — **генерируются**, руками не
править; меняется спека и генератор (`tools/lib/gen_rml.mjs`).

Что остаётся руками в редакторе: арт вместо плейсхолдеров, скиннинг (веса),
IK, тайминг клипов. Обмен файлами — через `.rev` (`docs/rive-cli-workflow.md`).
Экспорт `.rev` требует `rive login` — это делает Руслан.

Rive CLI установлен в `/opt/rive-cli`, симлинк `/usr/local/bin/rive`. Если
среда свежая: `docs/rive-cli-workflow.md`, раздел «Установка». Headless-
скриншоты CLI в этом контейнере не рендерят фигуры — картинку проверяет
лаборатория.

MCP-путь (`docs/rive-mcp-setup.md`) остаётся для работы прямо в открытом
редакторе, но основной канал — CLI.

## Чего не делать

- Не использовать `RiveAnimation.asset` и `stateMachineInputs` — их нет либо
  они устарели в `rive: 0.14.x`. Управление через Data Binding.
  Подробности — `docs/runtime-api-notes.md`.
- Не использовать `rive-flutter-legacy`.
- Не превращать заглушки скоростей затухания в продакшен-значения: по КП 15.4
  они настраиваются с сервера.
- Не подгонять каталог клипов под 108: расхождение 112/108 — вопрос к
  Заказчику, а не ошибка счёта (Q1).
- Не ходить в другие репозитории и не трогать другие экраны — только эта
  ветка и комната «Игра».
- В лаборатории всегда передавать имя State Machine при загрузке: без него
  web-рантайм играет первый таймлайн, и картинка есть, а машина стоит.
