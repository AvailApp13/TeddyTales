# assets/rive

Сюда кладутся экспортированные из Rive Editor файлы.

Требования к ригу — `docs/tz-animator-v2.md` (редакция 2, растровый
конвейер). Старый `docs/tz-animator.md` действует только в части, которую
редакция 2 не отменяет; таблица отличий — в её разделе 0.

| Файл | Что это | Константа в коде |
| --- | --- | --- |
| `bear_slow.riv` / `bear_joy.riv` | основной персонаж по героям: артборд и State Machine `bear_main`, 85 клипов + 6 служебных таймлайнов | `BearRigSpec.assetPath` |
| `birth_scene.riv` | сцена рождения, отдельный артборд, вне основной State Machine | `BearRigSpec.birthSceneAssetPath` |
| `demo_monster.riv` | временная заглушка, сторонний файл — см. ниже | `BearRigSpec.demoAssetPath` |

Пока `bear_main.riv` нет, `BearView` рендерит плейсхолдер вместо падения —
приложение собирается и запускается без рига.

## Требования к экспорту

- Тариф Rive **Cadet** ($9/мес) — безлимитный экспорт `.riv` для продакшена.
- Naming convention в файле: `Workspace → Admin → Options → Naming convention → snake_case`.
- Размер: не более 3 МБ для `bear_main.riv`, не более 4 МБ для `birth_scene.riv`
  (раздел 9 ТЗ аниматора).
- Имена артборда, State Machine и всех входов должны совпадать с
  `lib/bear/bear_rig_spec.dart`. Если в редакторе имена другие — правится один
  файл спецификации, код трогать не нужно.
- **Артборд сдаётся с прозрачным фоном.** У самого артборда не должно быть
  заливки — в редакторе это «цвет фона артборда», и рантайм её честно рисует.
  Фигур во весь артборд с видимой заливкой тоже быть не должно. Фон рисует
  приложение: персонаж стоит поверх сцены комнаты, и любая подложка в `.riv`
  просто закроет её. Отключить подложку из кода нельзя: рантайм умеет только
  вписать артборд в область. Проверяется автоматически — `tool/riv_lint.py`.
  Фигура во весь артборд с выключенной заливкой — это, наоборот, штатный
  приём: невидимая хит-зона под слушателя.

## Временная заглушка `demo_monster.riv`

Сторонний файл, взят только чтобы проверить пайплайн до прихода рига.
У него был собственный фон — заливка, повешенная прямо на артборд (`Fill`
с родителем `comp[0]`), с почти чёрным градиентом, из-за которого в приложении
вместо кремовой комнаты получался чёрный экран. Обе точки градиента погашены
до прозрачного:

    python3 tool/riv_paint.py set assets/rive/demo_monster.riv 809=00000000 810=00000000

Правка сделана по месту (цвет в `.riv` — это uint32 ARGB, длина файла и индексы
объектов не меняются). Удалить объект нельзя: ссылки на родителей в формате
идут по индексам. Удалить весь файл — можно и нужно, как только придёт
`bear_main.riv`.

## Порядок отрисовки правится после каждого экспорта

Рантайм рисует записанного в файл раньше **поверх** тех, кто идёт следом, а
редактор пишет слои в порядке панели Hierarchy. В сдаче v3 голова стояла выше
глаз, поэтому лицо было закрыто мехом. Порядок зафиксирован списком в
`tool/riv_rig.py` и применяется к экспортированному файлу:

    python3 tool/riv_rig.py inspect assets/rive/bear_main.riv   # показать порядок
    python3 tool/riv_rig.py fix     assets/rive/bear_main.riv   # применить

Тот же прогон выкидывает слои `arm_root_*` вместе с их картинками. Правка
пересобирает поток объектов целиком, поэтому пересчитывает все ссылки по
индексам — `objectId` дорожек, `interpolatorId` кейфреймов и `assetId`
картинок. Забыть `interpolatorId` — самая коварная ошибка: файл открывается и
рисуется правильно, но анимация молча перестаёт двигаться.

Пришёл новый экспорт из редактора — прогнать заново всю цепочку, по порядку:

    python3 tool/riv_rig.py blink   assets/rive/bear_main.riv   # моргание выкл.
    python3 tool/riv_rig.py place   assets/rive/bear_main.riv   # детали v4
    python3 tool/riv_rig.py fix     assets/rive/bear_main.riv   # порядок слоёв
    python3 tool/riv_rig.py mesh    assets/rive/bear_main.riv   # сетка на кофте
    python3 tool/riv_rig.py breathe assets/rive/bear_main.riv   # дыхание
    python3 tool/riv_rig.py giggle  assets/rive/bear_main.riv   # смех по тапу

Сетка (`mesh`) — деформация как у демо-дракона: на вдохе двигаются вершины
сетки на кофте, и контур тела реально надувается, а не масштабируется
картинка. Индексы треугольников в формате — varuint'ы, не uint16: на
неверной кодировке треугольники вырождаются и деталь молча исчезает.
`giggle` пишет анимацию смеха единым упругим телом (партитура: присел —
вытянулся — смялся, с затуханием) и при первом запуске дописывает в
стейт-машину вход trg_pet с переходами. После `mesh` дорожки обязаны быть
переписаны (`breathe`, `giggle`) — вставка вершин сдвигает индексы.

Риг v4 (текущий): семь деталей из одного нового эталонного фото
(docs/reference/bear-source-v2.png, нарезка — tool/make_rig_v4.py). Лицо
нарисовано прямо на голове: моргание убрано решением заказчика, отдельных
глаз, век и ртов больше нет — и швов на лице нет. `blink` оставляет
анимацию blink пустой (стейт-машину не трогаем), `place` кладёт картинки
parts-v4 и посадку из placements.json, `breathe` пишет idle из двух
неодинаковых вдохов (грудь, следом голова с ушами, лапы от плеча),
`fix` держит порядок отрисовки и выкидывает устаревшие детали. `clean`
нужен только при пересборке из parts-v2 и в цепочку v4 не входит.
